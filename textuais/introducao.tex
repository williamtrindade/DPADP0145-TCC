\chapter{Introdução}
\thispagestyle{headings}
    \par Este capítulo introduz o trabalho apresentando a contextualização do tema no âmbito do desenvolvimento de software moderno, o problema de pesquisa identificado na literatura, os objetivos geral e específicos que orientam a investigação, a metodologia de estudo de caso adotada e, por fim, a estrutura de organização dos demais capítulos.
    
    \section{Contextualização}
        \par O desenvolvimento de software moderno é marcado pela busca contínua por qualidade, o que, segundo \cite{livro:pressman:engenharia:2021}, envolve a criação de sistemas mais robustos, flexíveis e de fácil manutenção. A partir disso os padrões de arquitetura surgiram como soluções comprovadas para utilizar-se na criação de sistemas com alta complexidade. 
        
        
        \par Diante disso, o padrão Model-View-Controller (MVC) se destaca, servindo como a ``base arquitetural para muitos \textit{frameworks} de desenvolvimento web'' \cite{inproceedings:grove:2011}. Tendo isso em vista, tem-se o principal \textit{framework} da linguagem de programação PHP nos dias atuais, chamado Laravel, o qual adota por padrão o MVC como base arquitetural, sendo ele usado para a construção de aplicações web orientadas a interface gráfica, bem como meio para construir uma Interface de Programação de Aplicações (Application Programming Interface – API) \cite{laravel:docs}.
        
        \par O MVC, desde sua ideia original, propunha a divisão da aplicação em três componentes interconectados: o Modelo, responsável pela lógica de negócios e dados; a Visão, encarregada da apresentação; e o Controlador, que gerencia a interação do usuário. Essa separação de interesses oferecia uma base organizada que promovia o desacoplamento das responsabilidades do sistema \cite{artigo:reenskaug:1979}.
        
        \par Todavia, conforme as aplicações crescem em relação a sua complexidade, a manutenção e a testabilidade em sistemas que usam apenas o MVC tradicional acabam sendo mais difíceis, já que ele não visa resolver problemas de organização em todas as camadas do software. É nesse quesito que a Arquitetura Limpa proposta por \cite{livro:martin:cleanarch} foca, trazendo uma filosofia de design de software diferente, mas que faz uso de preceitos já estudados na ciência da computação por outros autores. Essa junção de técnicas visa minimizar os custos de evolução do software \cite{livro:martin:cleanarch}
        
        \par Essa arquitetura tem por preceito a organização do software em camadas concêntricas, onde as regras de negócio ficam no núcleo, isoladas dos detalhes de implementação como \textit{frameworks}, Interface de Usuário (User Interface - UI) e bancos de dados. Essa divisão é regida pela regra da dependência, a qual define que as dependências  do código devem apontar para dentro, protegendo o núcleo do software de influências externas \cite{livro:martin:cleanarch}.
        
        \par A relevância de se explorar a aplicação dos princípios da Arquitetura Limpa em APIs que usam o estilo arquitetural REST (\textit{Representational State Transfer}) desenvolvidas em Laravel vem do objetivo de buscar a longevidade e adaptabilidade do software, também de demonstrar como o uso da Arquitetura Limpa é capaz de isolar as regras de negócio do software, do \textit{framework}, que no caso desse trabalho é o Laravel, bem como separá-las de outras tecnologias, facilitando a manutenção futura.
        
        \par Nesse contexto, apesar da literatura atualmente abordar esses temas separadamente, percebe-se uma lacuna na mesma, no tocante a guias práticos e estudos de caso detalhados que mostram o processo de integração da Arquitetura Limpa com APIs REST desenvolvidas em Laravel, já estruturadas com o MVC. Essa carência pode dificultar a adoção de práticas arquiteturais avançadas por desenvolvedores, limitando o potencial das aplicações em termos de manutenibilidade e escalabilidade.
        
        \par Este trabalho de conclusão de curso, busca estudar e demonstrar de maneira prática, como os princípios da Arquitetura Limpa podem ser efetivamente implementados em uma API REST desenvolvida com Laravel, partindo de uma base MVC, com o objetivo de oferecer um caminho prático para a adoção da Arquitetura Limpa em projetos de software.

    \section{Problema de Pesquisa}
        \par A literatura acadêmica aborda tanto o \textit{framework} Laravel, por sua popularidade no desenvolvimento web, quanto a Arquitetura Limpa, como um modelo para a construção de sistemas manuteníveis. Contudo, a intersecção prática entre os dois temas carece de guias detalhados. Estudos como os de \cite{relacionado:bueno:2021} e \cite{relacionado:pinto:2021} demonstram a aplicação da Arquitetura Limpa no desenvolvimento de aplicações móveis com Flutter, enquanto trabalhos de \cite{artigo:souza:2021:clean}, \cite{relacionado:boff:2023} e \cite{inproceedings:isha:2023} exploram sua implementação em ecossistemas de backend distintos, como Java e Python. 
        
        \par Mesmo em pesquisas que analisam o impacto da Arquitetura Limpa em projetos Laravel, como a de \cite{inproceedings:nugroho:2022}, o foco recai sobre a medição dos resultados de manutenibilidade após a refatoração, sem detalhar o processo prático de transição. Dessa forma, evidencia-se uma lacuna específica no que tange a um estudo de caso que documente as etapas, as decisões de design e a reestruturação de código necessárias para migrar uma API REST da arquitetura MVC padrão do Laravel para os princípios da Arquitetura Limpa.
        
        \par Essa falta de abordagem consolidada pode dificultar a adoção de boas práticas arquiteturais pelos desenvolvedores, fazendo com que muitas soluções negligenciem os benefícios de longo prazo da Arquitetura Limpa, especialmente a manutenibilidade. O presente trabalho, portanto, visa investigar e demonstrar como os princípios da Arquitetura Limpa podem ser implementados em uma API REST baseada no padrão MVC do \textit{framework} Laravel.
        
    \section{Objetivos}
        \subsection{Objetivo Geral}

            \par O objetivo geral deste trabalho é detalhar, por meio de um estudo de caso prático, o processo de refatoração de uma API REST Laravel, estruturando-a segundo os princípios da Arquitetura Limpa. O estudo parte de uma aplicação com o padrão MVC nativo do \textit{framework} e propõe uma nova organização em camadas independentes, demonstrando as decisões de design, a reestruturação do código e o reposicionamento do padrão MVC na Arquitetura Limpa.

        \subsection{Objetivos Específicos}
            \par Este trabalho de conclusão de curso possui os seguintes objetivos específicos:

            \begin{itemize}

                \item Realizar uma busca na literatura sobre a relação entre Padrão de Arquitetura e Padrão de Projeto.
            
                \item Realizar uma busca na literatura sobre os princípios SOLID.
                
                \item Realizar uma busca na literatura sobre os fundamentos teóricos do padrão MVC e da Arquitetura Limpa.

                \item Realizar uma busca na literatura sobre a linguagem de programação PHP.
                
                \item Realizar uma busca na literatura sobre os conceitos do MVC no \textit{framework} Laravel.

                \item Selecionar uma API REST em Laravel que utilize a arquitetura padrão do \textit{framework} para servir como base.

                \item Documentar a reimplementação da API REST de referência escolhida.
                
                \item Redesenhar a API aplicando as camadas da Arquitetura Limpa.

                \item Comparar a estrutura e o fluxo da arquitetura redesenhada com o modelo original da API REST.

                \item Avaliar os cenários e discutir a viabilidade da adoção da Arquitetura Limpa.

            \end{itemize}
            
    \section{Metodologia}
        \par A metodologia adotada para a condução deste Trabalho de Conclusão de Curso apresenta uma abordagem qualitativa e de natureza aplicada, configurando-se como um estudo de caso prático. O principal objetivo é demonstrar, de forma detalhada e prática, o processo de implementação dos princípios da Arquitetura Limpa sobre uma API REST existente, desenvolvida com o \textit{framework} Laravel em sua estrutura padrão baseada no MVC.

        \par Inicialmente, foi realizada uma busca na literatura para estabelecer os fundamentos teóricos que norteiam o presente trabalho. Esta etapa focou na busca pela definição dos termos Padrão de Arquitetura e Padrão de Projeto no contexto do MVC e da Arquitetura Limpa, na investigação dos conceitos centrais do MVC, sua evolução para o contexto web (MVC-Web), os princípios de design de software SOLID, os preceitos da Arquitetura Limpa, incluindo sua organização em camadas e Regra da Dependência e uma base teórica sobre o \textit{framework} Laravel e a linguagem PHP.

        \par Em seguida, foi selecionada uma API REST base, proveniente de um tutorial do Programa de Educação Tutorial (PET) da UFSM, por sua clareza e aderência ao MVC padrão do Laravel. Um ambiente de desenvolvimento replicável e isolado foi construído utilizando Docker e Docker Compose, garantindo a consistência do projeto.

        \par A API base foi primeiramente codificada seguindo a estrutura MVC nativa do \textit{framework}. Subsequentemente, iniciou-se o processo de refatoração, que foi documentado passo a passo, aplicando sistematicamente os princípios e camadas da Arquitetura Limpa (como Entidades, Casos de Uso, Adaptadores de Interface e Frameworks \& Drivers) à estrutura original da API REST selecionada. 
        
        \par Toda etapa de desenvolvimento focou na refatoração do código e na redefinição das responsabilidades e introdução de abstrações, visando o desacoplamento e a melhoria da manutenção da API REST, sendo o processo documentado no presente trabalho.

        \par Também foi realizada uma análise comparativa entre a arquitetura original e a refatorada. Essa comparação foi feita em termos de estrutura de diretórios, utilizando diagramas de ``antes e depois'' para ilustrar a mudança de uma organização técnica para uma ``Arquitetura Gritante''. O fluxo de uma requisição em ambas as arquiteturas também foi contrastado por meio de diagramas de sequência.

        \par Por fim, procedeu-se à avaliação qualitativa, com o propósito de discutir a viabilidade da adoção da Arquitetura Limpa. Essa análise considerou os benefícios observados, como a melhoria na manutenibilidade e flexibilidade, bem como os aspectos que demandam maior atenção, como o aumento da complexidade inicial do projeto.
        
    \section{Estrutura do trabalho}
        \par O presente trabalho está organizado em cinco capítulos, com o objetivo de apresentar de maneira sequencial e lógica os tópicos abordados. 
    
        \par No primeiro capítulo, intitulado Introdução, é realizada a contextualização do tema, explorando a relevância dos padrões de arquitetura no desenvolvimento de software moderno e a crescente necessidade de sistemas manuteníveis. Apresenta-se o problema de pesquisa, que consiste na integração da Arquitetura Limpa em APIs REST baseadas em Laravel MVC. São definidos o objetivo geral e os objetivos específicos que norteiam a investigação e, por fim, detalha-se a metodologia de estudo de caso prático utilizada para a condução da pesquisa. 
    
        \par O segundo capítulo, Levantamento Bibliográfico, estabelece a fundamentação teórica necessária para o desenvolvimento do trabalho. Inicia-se com a distinção conceitual entre Padrão de Arquitetura e Padrão de Projeto, contextualizando o papel do MVC. Em seguida, aborda-se a evolução do MVC, desde sua concepção original no Smalltalk-80 até sua adaptação para o ambiente web (MVC-Web). O capítulo aprofunda-se nos princípios SOLID, que servem como base para a compreensão da Arquitetura Limpa, a qual é analisada em detalhe, cobrindo sua Regra da Dependência, a estrutura em camadas e um cenário de aplicação típico. Por fim, são apresentados os conceitos fundamentais da linguagem PHP e do \textit{framework} Laravel. 
    
        \par O terceiro capítulo, Desenvolvimento, descreve a fase prática da pesquisa e as etapas executadas para a resolução do problema proposto. Nele, é detalhada a construção da API REST base escolhida, que segue a estrutura padrão MVC do Laravel, e, posteriormente, documenta-se o processo de refatoração para a implementação da Arquitetura Limpa, camada por camada: Entidades, Casos de Uso, Adaptadores de Interface e Frameworks/Drivers. 

        \par O quarto capítulo, MVC versus Arquitetura Limpa, apresenta uma análise comparativa entre o modelo conceitual e o modelo prático obtido após a refatoração. São contrastadas a organização dos diretórios e o fluxo de processamento das requisições em ambas as arquiteturas. O quinto capítulo, Resultados e Discussões, dedica-se à avaliação qualitativa dos impactos decorrentes da adoção da Arquitetura Limpa, considerando aspectos como manutenibilidade, flexibilidade para novas implementações e aplicabilidade em projetos em andamento.

        \par Por fim, o trabalho é concluído com o capítulo de Considerações Finais, que sintetiza os resultados obtidos, seguido da seção de Referências Bibliográficas, que reúne as fontes consultadas ao longo da pesquisa.
