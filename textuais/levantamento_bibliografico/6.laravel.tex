\section{Laravel}
    \par Tendo em vista que o presente TCC aborda o Laravel como ferramenta para aplicar a Arquitetura Limpa, é necessário uma definição conceitual sobre seus princípios e filosofia, assim corroborando para o melhor entendimento dos código presentes durante o processo de refatoração.
    
    \par O Laravel é um \textit{framework} para o desenvolvimento de aplicações web em PHP, cuja primeira versão beta foi lançada em junho de 2011. A sua criação foi motivada pela insatisfação do seu idealizador, Taylor Otwell, com as limitações de \textit{frameworks} contemporâneos como o CodeIgniter. A filosofia central que norteia o Laravel é a de maximizar a ``felicidade do desenvolvedor'', um princípio que se manifesta através de código limpo, legível e de um ecossistema de ferramentas que visa simplificar tarefas comuns e acelerar o ciclo de desenvolvimento \cite{livro:stauffer:2023:laravel}.

    \par A fundação da arquitetura do Laravel é o seu \textit{container} de Inversão de Controle (IoC), que é a ferramenta que viabiliza a implementação de uma arquitetura limpa ao permitir a Injeção de Dependência \cite{livro:otwell:2013:laravel}. Este \textit{container} é o coração do ciclo de vida de uma requisição. Toda requisição HTTP para uma aplicação Laravel é direcionada para o arquivo public/index.php, que carrega o autoloader do Composer e inicializa a aplicação, criando uma instância do \textit{container} \cite{livro:stauffer:2023:laravel}.
    
    \par Em seguida, a requisição é encapsulada em um objeto \verb|Illuminate\Http\Request| e passada para o ``kernel'' da aplicação Laravel. O kernel, por sua vez, processa a requisição através de uma série de camadas de Middleware antes de finalmente direcioná-la para uma rota definida \cite{livro:stauffer:2023:laravel}.

    \par As rotas são os pontos de entrada de uma API e são definidas no arquivo routes/api.php. As rotas neste arquivo são, por padrão, \textit{stateless}, o que é fundamental para APIs REST. A definição de uma rota associa um verbo HTTP e um URI a uma ação, geralmente um método em um Controlador \cite{livro:stauffer:2023:laravel}.

    \par O Middleware atua como um sistema de filtros para as requisições HTTP. Antes de uma requisição chegar ao controlador, ela passa por um pipeline de Middlewares que podem inspecioná-la e até mesmo rejeitá-la. No contexto de uma API, os Middlewares são os locais ideais para implementar funcionalidades transversais. A sua aplicação mais comum é na autenticação, onde um middleware pode verificar a validade de um token de acesso, e no controle de frequência de requisições (rate limiting), que protege a API contra abuso \cite{livro:stauffer:2023:laravel}.

    \par O controller tem como responsabilidade receber a requisição HTTP e extrair os dados necessários do objeto Request \cite{livro:stauffer:2023:laravel}. Além disso ele pode delegar a execução da lógica de negócio para camadas mais internas, como classes de serviço ou casos de uso. A injeção de dependência é amplamente utilizada nos construtores e métodos dos Controllers para receber as abstrações (interfaces) das camadas de negócio, mantendo o controlador desacoplado da implementação concreta \cite{livro:otwell:2013:laravel}.

    \par Os modelos, implementados através do Eloquent ORM, representam a camada de acesso e persistência de dados. No contexto de uma API, a principal funcionalidade do Eloquent é a sua capacidade de serializar automaticamente modelos e coleções para o formato JSON quando retornados de um controlador . Para garantir que apenas os dados necessários sejam expostos, o Eloquent permite um controle preciso sobre a serialização através das propriedades \verb|$hidden| e \verb|$visible| na classe do modelo, um recurso de segurança essencial para desenvolver APIs \cite{livro:stauffer:2023:laravel}.

    \par Após o processamento pelo controlador e a serialização pelo Eloquent, a resposta é encapsulada num objeto \verb|Illuminate\Http\Response|, que então percorre o caminho inverso através do pipeline de Middleware, permitindo que cada camada modifique a resposta (por exemplo, adicionando cabeçalhos) antes de ser finalmente enviada de volta ao cliente \cite{livro:stauffer:2023:laravel}.

    \par Na Figura \ref{fig:figura_laravel1}, apresenta-se uma exemplificação simplificada da arquitetura do Laravel com base nos autores citados neste trabalho. O Laravel é estruturado em camadas, iniciando pela camada de entrada e \textit{framework}, que inclui o public/index.php, o Kernel, o Router e os Middlewares. Em seguida, a camada de aplicação contém os Controllers, responsáveis por orquestrar a lógica e direcionar o fluxo da requisição. Já a camada de negócio e dados concentra, opcionalmente, os Services ou Use Cases, que implementam a lógica de negócio, e obrigatoriamente os Models, representados pelo Eloquent, que realizam a persistência de dados. 
    
    \par Em algumas implementações, a lógica de negócio pode permanecer nos Controllers; contudo, a abordagem destacada pelos autores, ao delegar essa responsabilidade a componentes específicos, contribui para um maior desacoplamento e melhor organização do código. Por fim, conectando todos esses elementos, está o IoC Container, que viabiliza o desacoplamento e a injeção de dependências entre os componentes do \textit{framework}.

    \par Juntamente com seus componentes arquiteturais, o Laravel oferece uma interface de linha de comando chamada Artisan. Essencial para o ecossistema do \textit{framework}, o Artisan, impulsionado pelo componente Console do Symfony, disponibiliza um vasto conjunto de comandos que automatizam e aceleram tarefas repetitivas do desenvolvimento. Com ele, é possível gerar estruturas de código padronizadas, como Controllers, Models e Migrations, gerenciar o cache da aplicação, executar migrações de banco de dados e até mesmo criar comandos personalizados para necessidades específicas do projeto \cite{laravel:docs}.
